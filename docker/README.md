# Container image for the fixed UE4SS fork

A ready-to-run Palworld dedicated-server container image carrying the full
fixed fork stack: reviewed `libUE4SS.so`, the `FName_ToString.lua` address
override (leak fix), and the ops mods (AlphaRespawnScheduler, PalServerOptimizer,
ServerMaintenance, WorkProbe, UE4SSStatus).

Prebuilt images: `ghcr.io/qiiks/ue4ss-linux-palworld:server-v1.0.3`
(also tagged `server-latest`).

## What's inside

- Base: `obnyis/palworld-dedicated-server:libx11-gdb` (steamcmd, REST API,
  config templating, webhooks — all stock behavior preserved)
- Reviewed fork lib at `Pal/Binaries/Linux/ue4ss/libUE4SS.so` with
  `UE4SS_Signatures/FName_ToString.lua` (leak fix active on first boot)
- Ops mods pre-baked; `mods.txt` enables all five
- `ALWAYS_UPDATE_ON_START=false` by default — the container never force-updates
  the game at boot (the obnyis default destroys the install when steamcmd
  flakes). First run still installs the game via steamcmd; `UPDATE_ON_BOOT`
  can re-enable manual updates.
- `GuiConsoleEnabled=0` in UE4SS-settings.ini (the Linux GUI SIGSEGV class)

## Run

```bash
docker run -d --name palworld \
  -p 8211:8211/udp -p 8212:8212 \
  -v palworld-data:/palworld \
  -e SERVER_NAME="My Server" \
  -e SERVER_PASSWORD="" \
  -e ADMIN_PASSWORD="adminpass" \
  -e ENABLE_UE4SS=true \
  -e ALWAYS_UPDATE_ON_START=false \
  ghcr.io/qiiks/ue4ss-linux-palworld:server-latest
```

Environment variables are the same as the obnyis image (see
`obnyis/palworld-dedicated-server` on Docker Hub for the full list).

## How the UE4SS stack is installed

The obnyis image downloads a fragile stock UE4SS build on first boot. This
image instead ships the payload at `/opt/ue4ss-fork` and two scripts:

- `/scripts/fork-overlay.sh` (CMD wrapper): writes `PalServerUE4SS.sh` and the
  core payload into the volume before servermanager runs — `setup_ue4ss`
  sees the launcher and skips the stock download entirely.
- `/scripts/fork-postinstall.sh` (custom-script hook): re-copies the mods
  *after* a first-run steamcmd install (which wipes `ue4ss/Mods/`), and writes
  `mods.txt` to both `ue4ss/` and `ue4ss/Mods/` (the fork reads the latter).

Both are wired via the image's stock `CUSTOM_SCRIPT_ENABLED`/`CUSTOM_SCRIPT_PATH`
mechanism. If you mount your own game volume that already has the game
installed, the overlay still works (fresh_install is skipped).

## Build from source

```bash
# From the repo root:
docker build -t ghcr.io/qiiks/ue4ss-linux-palworld:server-latest docker/
```

The `docker/ue4ss/` payload is generated by `scripts/fetch-payload.sh`
(from a running server volume) — see the script header.
